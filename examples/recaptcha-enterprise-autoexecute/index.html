reCAPTCHA Enterprise — Universal key with AutoExecute

AutoExecute is a Universal-key feature that removes the manual execute() call: the reCAPTCHA library intercepts the requests you have told it to protect and attaches the token itself, as an X-Recaptcha-Token header. The SDK therefore mints no token at all — if it did, you would pay for two assessments and only one would be read.

Not yet verifiable end to end. ReachFive reads the captcha token from the request body, so a token that arrives only as a header is not consumed today. This page is built against the assumption that the backend will accept X-Recaptcha-Token; until it does, expect the header to be present in the log and the request to be rejected or treated as tokenless. The log below distinguishes the two carriers precisely so this stays visible.

Configuring the interception

AutoExecute only fires for the endpoints named in the key's policy settings in Google Cloud. Point those at the ReachFive identity routes you want covered — for example /identity/v1/signup and /oauth/token on your ReachFive domain. If the log shows a request with neither a header nor a body token, the interception pattern did not match that URL, which is the usual mistake.
